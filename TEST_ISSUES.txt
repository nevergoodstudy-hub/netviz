 ISSUE #1 — dependency_injector package not installed
===============================================================================
Severity  : HIGH
Category  : Environment / Dependency
Component : netops_toolkit/infrastructure/container.py
Status    : Open

Description:
  The 'dependency_injector' package is declared in pyproject.toml under
  [project.optional-dependencies] but is NOT installed in the current
  Python environment. This causes ImportError when any code path attempts
  to import the DI container module.

Reproduction Steps:
  1. python -m py_compile netops_toolkit/infrastructure/container.py
  2. Observe: ModuleNotFoundError: No module named 'dependency_injector'

Impact:
  Any production code relying on the DI container will crash at import time.
  Currently the test suite works because tests use conftest.py fixtures that
  mock/bypass the DI container.

Recommended Fix:
  pip install dependency-injector
  OR add it to the base [project.dependencies] instead of optional-dependencies.

 ISSUE #2 — asyncio.WindowsSelectorEventLoopPolicy deprecation
===============================================================================
Severity  : MEDIUM
Category  : Deprecation / Compatibility
Component : Multiple test files (via pytest-asyncio)
Status    : Open

Description:
  17 DeprecationWarnings are raised:
    "asyncio.WindowsSelectorEventLoopPolicy is deprecated as of Python 3.14
     and will be removed in Python 3.16"
  This comes from pytest-asyncio's internal event loop setup on Windows.

Reproduction Steps:
  1. python -m pytest tests/ -v
  2. Observe warnings in output referencing WindowsSelectorEventLoopPolicy

Impact:
  Tests will break on Python 3.16+ unless pytest-asyncio updates or the
  project explicitly sets a compatible event loop policy.

Recommended Fix:
  - Update pytest-asyncio to a version that supports Python 3.14+
  - OR set event_loop_policy in pyproject.toml [tool.pytest.ini_options]
  - OR add conftest.py fixture overriding the event loop policy

 ISSUE #3 — ResourceWarning: unclosed sqlite3.Connection
===============================================================================
Severity  : LOW
Category  : Resource Leak
Component : tests/test_services/test_scheduler_service.py (~lines 143, 176)
Status    : Open

Description:
  Two ResourceWarning messages about unclosed sqlite3.Connection objects
  are emitted during test_scheduler_service.py execution. This indicates
  that the scheduler service (or its test fixtures) do not properly close
  database connections in teardown.

Reproduction Steps:
  1. python -m pytest tests/test_services/test_scheduler_service.py -v -W all
  2. Observe: ResourceWarning: unclosed <sqlite3.Connection ...>

Impact:
  In long-running processes, unclosed DB connections accumulate, causing
  resource exhaustion. In tests, it is a code hygiene issue.

Recommended Fix:
  - Add explicit connection.close() in the scheduler service __del__ or
    cleanup method.
  - Add teardown fixture in the test to close the DB connection.

 ISSUE #4 — Starlette TemplateResponse parameter order deprecation
===============================================================================
Severity  : LOW
Category  : Deprecation / Compatibility
Component : netops_toolkit/web/app.py (TemplateResponse calls)
Status    : Open

Description:
  DeprecationWarning from Starlette:
    "The `name` argument in TemplateResponse(name=...) is deprecated.
     Use TemplateResponse(request, name=...) instead."
  The web app passes (name, context) positional args but Starlette now
  expects (request, name, context).

Reproduction Steps:
  1. python -m pytest tests/test_web/ -v
  2. Observe DeprecationWarning about TemplateResponse parameter order

Impact:
  Will break when Starlette removes backward compatibility for the old
  parameter order (likely in next major version).

Recommended Fix:
  Update all TemplateResponse calls in web/app.py to:
    TemplateResponse(request, name="template.html", context={...})

## 报告漏洞

如果你发现了安全漏洞，请**不要**在公开的 Issues 中报告。

请通过以下方式之一报告安全问题：

1. **GitHub Security Advisories** - 在仓库的 Security 标签页中创建私密安全公告
2. **电子邮件** - 发送邮件至项目维护者（请在仓库中查找联系方式）

### 报告内容

请在报告中包含以下信息：

- 漏洞的详细描述
- 复现步骤
- 潜在的影响范围
- 可能的修复方案（如果有）

### 响应时间

我们承诺：

- 在 **48 小时** 内确认收到报告
- 在 **7 天** 内提供初步评估
- 在 **30 天** 内发布修复（如确认为有效漏洞）

## 安全最佳实践

使用 NetViz 时，请注意以下安全建议：

### API 密钥安全

- 不要将 API 密钥硬编码在代码中
- 使用环境变量或安全的配置管理
- 定期轮换 API 密钥
- 不要在公开仓库中提交 `.env` 文件

### 网络捕获

- 仅在授权的网络上进行抓包
- 注意 PCAP 文件可能包含敏感信息
- 分析完成后及时删除敏感数据

### 威胁情报 API

- 注意 API 调用频率限制
- 不要滥用免费 API 配额
- 了解各服务提供商的数据使用政策

## 依赖安全

我们定期审查项目依赖的安全性：

- 使用 `npm audit` 检查前端依赖
- 使用 `pip-audit` 或 `safety` 检查 Python 依赖
- 及时更新有安全漏洞的依赖包
